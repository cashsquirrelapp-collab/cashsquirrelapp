# Direct PromptPay QR

Replaces only the PromptPay portion of INLINE_CHECKOUT.md. With `KRAROK_DIRECT_QR_ENABLED=true`, the customer clicks QR and sees the application's own scan dialog immediately. The server creates and confirms a PromptPay-only PaymentIntent using the authenticated account email; it returns the canonical Stripe QR image, amount, duration and order ID. No Stripe checkout form, extra Continue button, hosted payment page or client secret is sent for this flow. Card payments retain embedded Checkout. Prices remain THB159/1 calendar month, THB849/6 months and THB1490/12 months, single payment without auto-renewal.

The existing server-only order/reservation lock, exact catalog verification, immutable request persistence and idempotency model are shared with card Checkout. Direct QR has a real `intent_id`, never a fabricated Checkout session ID. Same-plan retries reuse the payment. Changing plan/method cancels and canonically retrieves the unpaid PaymentIntent before releasing the lock; a racing success is fulfilled instead. Unknown creates replay the persisted body/key only within the safe retention window. A failed/unknown cancellation cannot release or replace the order. Closing the dialog does not cancel or grant Pro, and no abandoned-order banner is shown. The 45-minute reservation controls reuse; this is not advertised as a bank/QR expiry time. Canonical cancellation is required before replacement.

Signed PaymentIntent success/failure/cancellation events are received on the existing webhook. Canonical retrieval checks mode, customer, account, reserved price metadata, amount received, currency, method and successful Charge before the existing idempotent fulfillment transaction. Owner-scoped polling uses the same evidence to repair delayed webhooks. Refunds/disputes invalidate the affected order. Calendar-month entitlement, administrator revoke/ban/unban and reset boundaries are preserved; an unresolved direct payment blocks account deletion and destructive admin changes. Browser callbacks never grant access.
